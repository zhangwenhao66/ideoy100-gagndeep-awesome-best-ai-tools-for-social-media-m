# Contributing

Thanks for contributing to `awesome-best-ai-tools-for-social-media-managers-2026`.

## Submission Rules

- Every tool must have a public `github.com` repository URL.
- No proprietary SaaS products, cloud-only tools, or listings without source code.
- Prefer OSI-approved licenses. If a repo uses a custom or source-available license, note that clearly in the pull request.
- Include the current star count, primary language, license, and last commit date from GitHub.
- Explain the social-media-manager use case in one or two sentences.
- If a category has fewer than five strong repos, document it as a gap instead of padding the list.

## Preferred Entry Format

Use this exact structure in `README.md`:

```md
#### [Tool Name](https://github.com/username/repo)
> **Description:** 80-150 words summarizing what the README says, what the tool does, key features, and the GitHub metadata.

- **GitHub:** [github.com/username/repo](https://github.com/username/repo)
- **Stars:** 12.3k ⭐
- **Language:** TypeScript
- **License:** MIT
- **Last Commit:** March 31, 2026
- **Category:** tag1, tag2
- **Best for:** specific use case
```

## Quality Bar

- Verify the repo is still public.
- Verify the repo fits social media manager workflows, not just general AI hype.
- Keep descriptions specific and avoid generic marketing copy.
- Do not submit duplicate repos under multiple names.

## Pull Requests

- Keep each pull request focused.
- If you update stars or commit dates, update only the affected entries.
- If you remove a repo, explain why it no longer meets the inclusion rules.
